# 多模态图文检索 RAG 应用技术文档

## 1. 项目概述

### 1.1 项目名称
多模态图文检索 RAG 智能知识问答系统

### 1.2 项目定位
本项目面向非结构化知识资产管理与智能检索问答场景，构建了一个支持文档解析、图文联合索引、语义检索、重排优化与答案生成的一体化 RAG 应用。系统能够将 PDF、Word 等文档中的正文内容、表格信息和图片内容统一纳入知识库，并基于大模型实现“可追溯、有依据”的问答能力。

### 1.3 项目目标
本项目旨在解决传统文档检索和问答系统中存在的以下问题：

- 文档内容分散，人工查阅效率低
- 仅支持关键词匹配，难以理解自然语言问题
- 纯文本知识库无法覆盖图片、图示、图表等信息
- 回答缺乏出处，难以验证答案可靠性
- 多轮优化能力不足，检索质量受提示词影响较大

因此，本项目以“多模态理解 + 语义检索 + 生成增强”为核心思路，打造一个适用于比赛展示与真实业务扩展的智能知识服务系统。

## 2. 应用场景与实际价值

### 2.1 典型应用场景

#### 场景一：科研资料与论文辅助检索
针对论文、技术报告、规范文档、实验资料等，用户可以直接通过自然语言提问，例如：

- 某篇文档的研究目标是什么？
- 某个实验方法有哪些步骤？
- 文中图片反映了什么结构或流程？
- 不同章节中对某一概念的描述有何差异？

系统能够快速定位相关段落、页面与图片描述，减少人工通读文档的时间成本。

#### 场景二：企业知识库与制度文档问答
在企业内部制度、培训资料、产品文档、技术手册等场景中，员工可以通过自然语言快速查询知识点，例如：

- 某项流程如何执行？
- 某制度适用范围是什么？
- 某图示对应的设备结构是什么？
- 某参数在哪一页、哪个部分提到？

该能力能够显著提升内部知识复用效率。

#### 场景三：教育与培训材料智能辅学
在课程讲义、教材、培训文件中，系统可以作为智能学习助手，支持：

- 文本知识点快速提炼
- 图文结合内容理解
- 重点结论回溯
- 基于证据的问答与定位

#### 场景四：多模态资料归档与知识治理
对于包含流程图、结构图、截图、插图、表格的复杂文档，仅依赖文本检索常常无法完整覆盖内容。本项目通过图片描述生成与统一向量化索引，使图片信息也可被检索和引用，提升知识治理完整度。

### 2.2 目标用户

- 需要管理大量文档资料的科研团队
- 有知识库建设需求的企业组织
- 需要进行资料检索和问答辅助的教师与学生
- 希望将图文资料沉淀为智能问答资产的开发者与产品团队

### 2.3 项目价值总结

本项目的核心价值体现在以下几个方面：

1. **提升检索效率**：将“人工翻文档”升级为“自然语言直达知识点”。
2. **增强理解能力**：支持语义检索，而不局限于关键词命中。
3. **覆盖多模态信息**：图片内容可通过视觉模型生成描述并进入知识库。
4. **提高回答可信度**：回答附带引用依据，支持人工核验。
5. **具备优化空间**：可通过提示词、重排策略、切块策略和模型替换持续提升效果。

## 3. 系统功能设计

### 3.1 文档接入能力
系统支持将外部文档导入知识库，目前支持的文档类型包括：

- PDF
- DOC
- DOCX

上传后系统会自动完成：

- 文档存储
- 文件去重
- 文本解析
- 文本分块
- 图片抽取
- 图片描述生成
- 向量化索引构建

### 3.2 多模态知识抽取能力
项目不只处理纯文本内容，还支持从文档中提取图片，并调用视觉大模型对图片进行文字描述，再将描述结果写入向量索引。这样，用户即使使用自然语言描述图片内容，也有机会检索到对应资料。

### 3.3 分层切块与摘要索引能力
系统对文档内容采用父子分块策略：

- 父块用于承载较完整的语义片段，并生成摘要
- 子块用于细粒度内容召回
- 摘要索引与原文索引结合，兼顾概括性与细节性

这种设计有助于兼顾召回范围和答案可读性。

### 3.4 语义检索与重排能力
针对用户问题，系统首先执行向量相似度检索，再基于重排模型对候选证据进行二次排序，从而提升最终进入生成阶段的上下文质量。该机制有助于降低无关片段进入答案生成过程的概率。

### 3.5 基于证据的问答生成能力
在答案生成阶段，系统会将检索到的候选证据作为上下文输入大模型，要求模型严格依据证据作答，避免脱离知识库内容自由发挥，从而增强答案可信性与可追溯性。

### 3.6 文档管理能力
系统支持：

- 文档列表查看
- 文档删除
- 文档覆盖式重建
- 重复文档识别

便于知识库持续维护和更新。

## 4. 技术方案与实现思路

### 4.1 总体架构思路
本项目整体采用“文档接入层—知识加工层—检索层—生成层—应用层”的架构思路：

1. **文档接入层**：负责接收 PDF/Word 文档。
2. **知识加工层**：负责解析文本、提取图片、生成摘要、构建父子分块。
3. **向量检索层**：负责将文本摘要、子块内容、图片描述写入向量数据库并执行相似度检索。
4. **重排优化层**：对初步召回结果进行相关性重排。
5. **答案生成层**：将高相关上下文输入大模型生成最终答案。
6. **应用接口层**：通过 API 或前端页面提供交互能力。

### 4.2 后端框架
项目后端基于 FastAPI 构建，具备以下特点：

- 接口开发效率高
- 支持异步能力
- 便于后续接入前端和服务部署
- 适合构建轻量级、高可扩展的 AI 应用服务

### 4.3 数据与存储设计
项目使用两类存储：

#### 结构化存储
使用 SQLite 保存文档与索引元数据，例如：

- 文档信息
- 分块信息
- 图片信息
- 文件路径与状态信息

#### 向量存储
使用 Chroma 作为向量数据库，存储以下内容的向量表示：

- 父块摘要
- 子块文本内容
- 图片描述文本

这种设计使得系统能够同时支持摘要级检索、细粒度文本检索和图片语义检索。

### 4.4 多模态处理机制
项目中的多模态能力主要体现在图片处理流程上：

1. 从 PDF/Word 中提取图片
2. 调用视觉大模型为图片生成描述
3. 将图片描述文本写入向量索引
4. 在检索阶段与文本块共同参与召回

该方案的优点是工程实现相对稳定，不依赖复杂的跨模态统一编码器，也便于后续继续替换成更强的视觉编码方案。

### 4.5 提示词工程设计
项目中至少存在三类提示词能力：

- 文本摘要提示词：用于将长文本压缩为可索引摘要
- 查询改写提示词：用于将用户输入改写为更适合检索的表达
- 最终回答提示词：用于约束模型依据证据回答，并输出引用内容

提示词工程在本系统中非常关键，它会直接影响：

- 检索表达是否准确
- 候选证据是否聚焦
- 答案是否可信
- 引用是否规范

### 4.6 Rerank 重排优化
项目在初步向量检索后增加了 Rerank 模块，用于重新排序候选结果。其作用包括：

- 提升前几条证据的相关性
- 降低噪声片段干扰
- 增强最终答案的聚焦程度
- 为比赛展示提供更明显的优化点与对比空间

### 4.7 可扩展性设计
当前系统已经具备进一步扩展的基础，后续可以继续增加：

- 更多文件格式支持
- 多轮对话记忆
- 用户权限与知识库隔离
- 更强的多模态编码方式
- 在线评测与自动化指标面板

## 5. 项目亮点

### 5.1 图文统一纳入知识库
相比仅处理文本的传统 RAG，本项目能够对文档中的图片信息进行抽取与描述建模，从而实现图文一体的知识检索。

### 5.2 摘要索引与细粒度索引结合
通过摘要 + 子块双通道索引，系统在保证召回范围的同时，也保留了细节定位能力。

### 5.3 基于证据的回答约束
最终答案不是直接“自由生成”，而是建立在召回证据基础上，有助于减少幻觉问题，增强回答可信度。

### 5.4 具备可量化优化空间
本项目天然适合做效果对比实验，例如：

- 开启/关闭 Rerank 的效果对比
- 不同提示词版本的检索效果对比
- 摘要索引与子块索引的效果对比
- 文本单模态与图文多模态的效果对比

这非常适合创新大赛中的“技术方案 + 实证优化”展示方式。

### 6.3 检索效果测试指标

#### 6.3.1 Recall@K（召回率）
**定义**：标准证据是否出现在前 K 个召回结果中。

**适用目的**：衡量系统“能不能找到对的内容”。

**建议设置**：

- Recall@1
- Recall@3
- Recall@5

**测试方法**：

1. 对每个测试问题发起一次检索。
2. 记录前 K 条返回结果。
3. 检查标准证据是否出现在前 K 条结果内。
4. 若出现，则该题记为 1；否则记为 0。
5. 对所有测试题求平均值。

**计算公式**：

\[
Recall@K = \frac{命中标准证据的问题数}{总测试问题数}
\]

| 指标 | 数值 | 备注 |
| --- | --- | --- |
| Recall@1 |  |  |
| Recall@3 |  |  |
| Recall@5 |  |  |

#### 6.3.2 Precision@K（精确率）
**定义**：前 K 个召回结果中，有多少比例是真正相关的。

**适用目的**：衡量召回结果中噪声是否过多。

**测试方法**：

1. 对每个测试问题取前 K 个召回结果。
2. 人工标注每条结果是否相关。
3. 统计前 K 中相关结果数量。
4. 对所有问题求平均值。

**计算公式**：

\[
Precision@K = \frac{前K条结果中的相关结果数}{K}
\]

**建议设置**：

- Precision@3
- Precision@5

| 指标 | 数值 | 备注 |
| --- | --- | --- |
| Precision@3 |  |  |
| Precision@5 |  |  |

#### 6.3.3 MRR（Mean Reciprocal Rank，平均倒数排名）
**定义**：第一个正确证据出现的位置越靠前，MRR 越高。

**适用目的**：衡量正确证据是否排在前面。

**测试方法**：

1. 对每个问题记录第一条正确证据出现的位置 rank。
2. 若未命中，则该题得分为 0。
3. 若命中，则该题得分为 \(1/rank\)。
4. 对所有题目求平均值。

**计算公式**：

\[
MRR = \frac{1}{N} \sum_{i=1}^{N} \frac{1}{rank_i}
\]

### 6.6 提示词优化效果测试

本项目非常适合做“提示词工程优化”对比实验，这是比赛展示中很有亮点的一部分。

#### 6.6.1 测试目标

## 9. 项目不足与问题分析

虽然项目已经具备较完整的 RAG 应用雏形，但当前仍存在一些可继续优化的方面：

### 9.1 多模态理解仍偏“图片转文字描述”范式
当前图片检索主要依赖视觉模型先生成文字描述，再通过文本向量参与召回。这种方式实现成本低、兼容性好，但对复杂图表、公式图、流程关系图的表达能力仍可能不足。

### 9.2 检索效果对提示词和切块策略较敏感
在知识库规模扩大后，不同 chunk 粒度、摘要质量、查询改写方式会明显影响召回结果，需要通过实验进行持续调优。

### 9.3 缺少自动化评测闭环
当前效果评测仍以人工整理测试集和人工标注为主，后续可引入自动化评测脚本与可视化指标看板，提高迭代效率。

### 9.4 缺少多轮上下文记忆能力
当前系统更适合单轮问答，若后续用于真实业务场景，多轮追问、上下文承接和会话记忆将变得更加重要。

### 9.5 图片与文本之间的细粒度对齐仍可增强
目前图片与文本块的关联关系还有进一步提升空间，例如建立图片与相邻段落、图题、表题之间的显式关联，以增强图文联合推理能力。

## 10. 未来改进方向

### 10.1 引入更强的多模态向量建模方案
未来可以探索统一图文嵌入模型或跨模态检索模型，而不仅仅依赖“图片描述文本化”的方式，以提升复杂图片场景的检索精度。

### 10.2 建设自动化评测体系
后续可以将测试问题集、标准答案、标准证据、评分规则沉淀为自动化评测模块，形成：

- 检索评测脚本
- 问答评测脚本
- 多模态专项评测脚本
- 提示词对比实验面板

### 10.3 增强查询改写与意图识别能力
不同用户的提问方式差异很大，未来可增加：

- 问题意图分类
- 关键词增强
- 多路查询生成
- HyDE 等检索增强方法

进一步提升复杂问题召回能力。

### 10.4 引入混合检索机制
未来可以尝试融合：

- 向量检索
- 关键词检索
- BM25
- 元数据过滤
- 规则检索

构建混合检索体系，以提升特定领域文档的稳定性。

### 10.5 面向真实业务扩展知识治理能力
后续可增加：

- 多用户系统
- 权限控制
- 知识库分库管理
- 文档版本管理
- 增量更新能力
- 在线运营分析

使项目从比赛原型进一步演进为可落地应用。

### 10.6 提升答案表现形式
未来可以进一步增强前端展示与回答组织方式，例如：

- 证据高亮定位
- 引用跳转到页码
- 图文联动展示
- 回答结构化摘要卡片
- 多文档对比视图

从而提升用户体验和展示效果。
