# 多模态 RAG 项目接口测试用例文档

> 文档用途：供前端联调、自测、测试同学、演示验收时使用。
>
> 当前状态更新：系统设置相关接口已由后端实现，现可直接纳入测试范围。

---

## 1. 测试环境说明

### 1.1 服务地址

- 后端服务：`http://localhost:8010`
- 接口前缀：`/api`
- Swagger：`http://localhost:8010/docs`

### 1.2 建议测试工具

- Swagger UI
- Postman
- Apifox
- curl
- 前端本地联调页面

### 1.3 测试准备文件建议

请准备以下几类样本文件：

1. 正常 PDF 文件
2. 正常 DOCX 文件
3. 可解析 DOC 文件
4. 重复文件
5. 错误格式文件
6. 伪装扩展名 DOC 文件

## 4. 文档管理接口测试

### TC-DOC-LIST-001 获取文档列表

- 接口：`GET /api/rag/documents`
- 预期：返回数组，每项包含 `id/file_name/status/created_at`

### TC-INGEST-001 单个 PDF 上传成功

- 接口：`POST /api/rag/ingest`
- 参数：`files=@test.pdf`，`overwrite=false`
- 预期：`200`，`items[0].success=true`

### TC-INGEST-002 多文件混合上传成功

- 接口：`POST /api/rag/ingest`
- 参数：多个 `files`
- 预期：`total`、`succeeded`、`failed` 与实际一致

### TC-INGEST-003 重复上传不覆盖

- 参数：重复文件，`overwrite=false`
- 预期：`already_exists=true`，`overwritten=false`

### TC-INGEST-004 重复上传并覆盖

- 参数：重复文件，`overwrite=true`
- 预期：`overwritten=true`

### TC-INGEST-005 非法格式上传

- 参数：如 `.txt`
- 预期：对应项 `success=false`，`error` 有明确提示

### TC-DOC-UPDATE-001 更新已有文档成功

- 接口：`PUT /api/rag/documents/{document_id}`
- 预期：返回 `old_document_id/new_document_id`

### TC-DOC-DELETE-001 删除已有文档成功

- 接口：`DELETE /api/rag/documents/{document_id}`
- 预期：返回 `status=deleted`

## 5. 问答接口测试

### TC-ASK-001 非流式正常问答

- 接口：`POST /api/rag/ask`
- 请求：

```json
{
  "question": "请总结研究生培养计划的主要要求",
  "stream": false
}
```

- 预期：
  - HTTP `200`
  - 返回 `answer`
  - 返回 `citations`
  - 返回 `rerank_status`

### TC-ASK-002 验证 rerank_status 字段

- 预期字段：
  - `enabled`
  - `used`
  - `fallback`
  - `mode`
  - `provider`
  - `model`
  - `reason`
  - `requested_top_n`
  - `returned_count`

### TC-ASK-STREAM-001 SSE 流式输出正常

- 接口：`POST /api/rag/ask`
- 请求：`stream=true`
- 预期：
  - `Content-Type: text/event-stream`
  - 有 `token`
  - 有 `citations`
  - 有 `done`

## 6. 系统设置接口测试（已实现）

---

### TC-CONFIG-ALL-001 获取配置总览

- 接口：`GET /api/rag/config/all`
- 预期：
  - HTTP `200`
  - 返回 `model`
  - 返回 `reranker`
  - 返回 `retrieval`

### TC-CONFIG-MODEL-001 获取模型配置

- 接口：`GET /api/rag/config/model`
- 预期：
  - HTTP `200`
  - 返回 `llm`
  - 返回 `embedding`
  - 返回 `vision`
  - 返回 `source`
  - `api_key` 为脱敏值 `******` 或空字符串

### TC-CONFIG-MODEL-002 更新模型配置成功

- 接口：`PUT /api/rag/config/model`
- 请求示例：

```json
{
  "llm": {
    "api_base": "https://dashscope.aliyuncs.com/compatible-mode/v1",
    "api_key": "",
    "model_name": "qwen-plus",
    "timeout": 120
  },
  "embedding": {
    "api_base": "https://dashscope.aliyuncs.com/compatible-mode/v1",
    "api_key": "",
    "model_name": "text-embedding-v3"
  },
  "vision": {
    "enabled": false,
    "api_base": "https://dashscope.aliyuncs.com/compatible-mode/v1",
    "api_key": "",
    "model_name": "qwen-vl-max-latest"
  },
  "apply_mode": "persist_and_reload"
}
```

- 预期：
  - HTTP `200`
  - 返回：

```json
{
  "message": "模型配置已更新",
  "applied": true,
  "need_restart": false
}
```

### TC-CONFIG-MODEL-003 更新模型配置后问答热生效

- 步骤：
  1. 更新模型配置
  2. 再次调用问答接口
- 预期：
  - 新请求使用新的数据库配置
  - 无需手动重启后端

---

### TC-CONFIG-RERANK-001 获取 Reranker 配置

- 接口：`GET /api/rag/config/reranker`
- 预期：返回 `enabled/base_url/timeout/health_status`

### TC-CONFIG-RERANK-002 更新 Reranker 配置成功

- 接口：`PUT /api/rag/config/reranker`
- 请求示例：

```json
{
  "enabled": false,
  "base_url": "http://127.0.0.1:9998",
  "timeout": 60,
  "apply_mode": "persist_and_reload"
}
```

- 预期：
  - HTTP `200`
  - 返回 `need_restart=false`

### TC-CONFIG-RERANK-003 关闭 reranker 后问答生效

- 步骤：
  1. 调用 `PUT /api/rag/config/reranker`，传 `enabled=false`
  2. 再次调用 `POST /api/rag/ask`
- 预期：
  - `rerank_status.enabled=false`
  - `rerank_status.mode=disabled`
  - 系统跳过 rerank 但仍可正常回答

---

### TC-CONFIG-RET-001 获取检索参数

- 接口：`GET /api/rag/config/retrieval`
- 预期：返回 `top_k/keyword_top_k/final_top_n/description`

### TC-CONFIG-RET-002 更新检索参数成功

- 接口：`PUT /api/rag/config/retrieval`
- 请求示例：

```json
{
  "top_k": 20,
  "keyword_top_k": 10,
  "final_top_n": 6,
  "apply_mode": "persist_and_reload"
}
```

- 预期：
  - HTTP `200`
  - 返回 `current.top_k=20`
  - 返回 `need_restart=false`

### TC-CONFIG-RET-003 检索参数非法

- 请求示例：

```json
{
  "top_k": 10,
  "keyword_top_k": 5,
  "final_top_n": 30,
  "apply_mode": "persist_and_reload"
}
```

- 预期：
  - HTTP `400`
  - 返回：

```json
{
  "detail": "final_top_n 不能大于 top_k + keyword_top_k"
}
```

### TC-CONFIG-RET-004 检索参数更新后问答热生效

- 步骤：
  1. 记录当前参数
  2. 更新检索参数
  3. 再发起问答
- 预期：
  - 新请求使用新参数
  - `rerank_status.requested_top_n` 与更新后的 `final_top_n` 一致

## 8. 通过标准

本轮配置接口补齐后的核心通过标准：

1. 前端系统设置页不再提示“后端尚未实现”。
2. `config/all`、`config/model`、`config/reranker`、`config/retrieval` 均可正常返回。
3. 三个更新接口均可正常保存。
4. `need_restart=false` 时，新请求可直接体现新配置。
5. `POST /api/rag/ask` 返回中包含 `rerank_status`，且能反映 reranker 当前配置状态。

---

## 9. 给测试和前端的特别提醒

1. 模型配置、reranker 配置、检索参数配置接口现在已实现，不再是预留项。
2. 配置更新后，一般不需要重启后端；新请求会按数据库配置优先执行。
3. 若查询接口中的密钥字段显示为 `******`，这是正常脱敏行为。
4. 若更新时不想改密钥，请传空字符串。
